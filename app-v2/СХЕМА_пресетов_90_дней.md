# Схема anchors_seeds.json для 90-дневных пресетов (для Python-генератора)

Файл читает `_buildDayFromSeed()` в cabinet.html/index.html. День берётся так:
`dayIds = item.days[(dayIndex - 1) % item.days.length]` — то есть длина `days`
может быть ЛЮБОЙ: 8 → цикл по 8, 90 → уникальные 90 дней. Ничего в коде менять не надо.

## Структура файла

```json
{
  "note": "строка-комментарий (не используется кодом)",
  "count": 238,
  "anchors": [
    {
      "anchor": {
        "kcal": 2652,      // целевые калории якоря
        "p": 201,          // белок, г
        "f": 88,           // жиры, г
        "c": 265,          // углеводы, г
        "meal": 5,         // число приёмов (длина slots)
        "group": "f80p",   // весовая группа: m70|m90|m90p|f60|f80|f80p
        "pct": 3.35,       // доля профилей (для выбора ближайшего якоря)
        "cum": 3.3
      },
      "slots": ["breakfast","lunch","snack","dinner","snack"],
      "days": [
        ["fr_135139","vg_085","vt_001","fr_2133","vt_069"],   // день 1: id рецептов по слотам
        ["fr_209878","vg_033","vg_090","fr_207890","pdf_540021"], // день 2
        ...                                                    // → 90 массивов для 90 дней
      ]
    },
    ...
  ]
}
```

## Требования к генерации

1. **Длина `days` = 90** (сейчас 8). Каждый день — массив id длиной ровно `len(slots)`.
2. **id рецептов** — только существующие в актуальном `recipes.json`.
3. Каждый день должен собираться в ±3% по Б/Ж/У от якоря (движок доводит
   ребалансом, но стартовая близость критична — иначе фолбэк в мотор).
4. Разнообразие: не повторять блюдо чаще, чем раз в N дней (сейчас в 8-дневных
   пресетах повторов внутри пресета почти нет — сохрани принцип, при 90 днях
   допустимы повторы с шагом ≥5 дней).
5. `pickAnchor()` выбирает якорь по близости (kcal, p, f, c, meal, group) — сами
   якоря (их 238) можно оставить прежними, меняется только содержимое `days`.
6. Валидация: `python3 validate_presets.py` (уже есть в проекте).

## Как подключить

Просто заменить файл `anchors_seeds.json` и перезалить (в v2: `bash deploy-v2.sh` —
он зальёт его с gzip). Кэш у клиента: файл грузится с `force-cache`, поэтому при
замене надо поднять версию приложения (version.json) или сменить имя файла.
