## ЧАСТЬ 2 — Бэкенд: продление плана 91→180 + честные 90 дней (когда будешь готов)

Это то, без чего доплата продлевает только **время доступа**, но план стоит на 90 днях

Файл: `yandex-backend/index.js` + одна SQL-правка. **Внимание: бэкенд общий с продом — правь аккуратно.**

### Шаг 2.0 — ВАЖНО: разрешить обновление веса на залоченном профиле (иначе P3a не сохраняется)
**Симптом (ты его поймал):** после перевзвешивания новый вес не сохраняется / откатывается.
**Причина:** `handleProfileSave` при `wasLocked` игнорирует все FIXED-поля, в т.ч. вес:
```
const FIXED_FIELDS    = ['gender', 'height', 'age', 'current_weight', 'desired_weight'];
```
**Правка (index.js, ~строки 278–279):** вынести вес и желаемый вес в редактируемые
(30-дневный гейт держит фронт; пол/рост/возраст остаются неизменяемыми):
```
const FIXED_FIELDS    = ['gender', 'height', 'age'];
const EDITABLE_FIELDS = ['activity', 'goal', 'exclusions', 'current_weight', 'desired_weight'];
```
После этого перезалей функцию (Шаг 2.3) — и P3a будет сохранять новый вес.
_(Фронт уже всё шлёт правильно и пересчитывает КБЖУ; блокировал только бэкенд.)_

### Шаг 2.1 — SQL: добавить колонку `periods` в таблицу `subscriptions`
В консоли YDB выполни (один раз):
```sql
ALTER TABLE subscriptions ADD COLUMN periods Uint32;
```
_(Существующие подписчики получат `periods = NULL`; код ниже трактует NULL как 1.)_

### Шаг 2.2 — правка `index.js` (3 маленькие правки)

**(1) Строка 35 — честный срок доступа (решение P2a):**
```
было:  const ACCESS_DAYS    = 31;   // срок доступа после оплаты
стало: const ACCESS_DAYS    = 95;   // ~90 дней плана + буфер
```

**(2) Функция `dbInsertOrExtendSub` (~строки 142–170) — считать оплаченные периоды.**
Рядом с чтением `expires_at` добавь чтение `periods`, увеличивай на 1 при каждой оплате
и клади в UPSERT:
```js
// читаем текущий срок И число периодов
let base = now, periods = 1;
await driver.tableClient.withSession(async (session) => {
  const sel = `DECLARE $email AS Utf8;
    SELECT expires_at, periods FROM subscriptions WHERE email = $email;`;
  const { resultSets } = await session.executeQuery(sel, { '$email': TypedValues.utf8(email) });
  const rows = TypedData.createNativeObjects(resultSets[0]);
  if (rows.length) {
    const cur = new Date(rows[0].expires_at).getTime();
    if (cur > now) base = cur;                     // ещё активна → продлеваем от старой даты
    periods = (Number(rows[0].periods) || 1) + 1;  // повторная оплата → +1 период
  }
});
const expires = base + ACCESS_DAYS * 24 * 60 * 60 * 1000;
```
И в самом `UPSERT` добавь колонку `periods`:
```
UPSERT INTO subscriptions (email, phone, prodamus_order_id, paid_at, expires_at, updated_at, periods)
VALUES ($email, $phone, $order, $paid, $expires, $upd, $periods);
```
объявив и передав её:
```
DECLARE $periods AS Uint32;
...
'$periods': TypedValues.uint32(periods),
```

**(3) Функция `dbGetSubByEmail` (~строки 175–190) — возвращать `plan_days`.**
Добавь `periods` в SELECT и посчитай `plan_days = periods*90`:
```js
const q = `DECLARE $email AS Utf8;
  SELECT email, prodamus_order_id, expires_at, periods FROM subscriptions WHERE email = $email;`;
...
const per = Number(rows[0].periods) || 1;
result = { email, orderId: String(rows[0].prodamus_order_id || ''), expires: exp,
           active: Date.now() < exp, plan_days: per * 90 };
```
Затем убедись, что ответы ручек **`/check`** и **`/login-verify`** отдают это `plan_days`
наружу (там, где формируется JSON с `expires` — добавь рядом `plan_days`).
