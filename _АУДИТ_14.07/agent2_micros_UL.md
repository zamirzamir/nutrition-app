# Аудит №2 — Риск превышения UL микронутриентов в ДНЕВНЫХ связках блюд

Дата: 14.07.2026 · Аудитор: субагент №2 · Режим: READ-ONLY (ничего не менял)

## TL;DR (вердикт)

**Реальных UL-нарушений в пресетах для целевого клиента НЕТ.** Пресеты
(`anchors_seeds.json`) собраны скриптом `build_super_presets.py`, который при генерации
**отбраковывает любой день, где суточная сумма превышает UL** (строка 125:
`if any(M[key] > ULcap[key] for key in UL): continue`). Проверка — на СУТКИ, не на блюдо.
Поэтому по построению каждый пресет-день при СВОЁМ весе группы ≤ UL.

- **Пресеты, свой вес группы (7140 дней × 13 нутриентов):** 0 нарушений IOM UL.
- **m90/m90p якоря (то, что получит тестовый персонаж — мужчина, набор массы):**
  максимум упирается ровно в x1.000 UL по ниацину (B3) и фолату (B9), остальное ниже.
- **Опасность стакинга — только теоретический worst-case** (ручные замены/подбор
  «самых насыщенных» блюд в один день). Он реален как вектор, но требует намеренных
  действий пользователя И отсутствия рантайм-защиты (см. раздел 4 — это единственная
  находка, требующая внимания).

---

## 1. Как хранятся микронутриенты (схема)

- `recipes.json` (3736 рецептов): микронутриентов **НЕТ** — только `portions` (КБЖУ на
  6 весовых групп `m70/m90/m90p/f60/f80/f80p`).
- **Микро лежат отдельно** — `micronutrients_per_portion.json` → `dishes[<id>].groups[<группа>]`:
  готовые суммы 26 нутриентов на порцию каждой из 6 групп (+ `per100g`). Покрытие полное:
  все 1117 id из пресетов и все 3736 рецептов присутствуют, пропусков нет.
- `micronutrients.json` — база на 100г ингредиентов (USDA FoodData Central), UL там **нет**.
- Единицы (из `note_units`): A/D/K/B9/B12 — мкг; C/E/B1/B2/B3/B5/B6 — мг; минералы — мг,
  **selenium/iodine — мкг**; omega/fiber/sugar/sat_fat — г; cholesterol — мг.

### UL-значения (взяты официальные — US IOM/NIH, взрослые)
Совпадают с зашитыми в `add_recipe.py:28` и `build_super_presets.py:46`:
```
vitamin_a 3000 мкг RAE · b3(ниацин) 35 мг · b6 100 мг · b9(фолат) 1000 мкг · c 2000 мг
vitamin_d 100 мкг · vitamin_e 1000 мг · calcium 2500 мг · iron 45 мг · zinc 40 мг
selenium 400 мкг · iodine 1100 мкг · phosphorus 4000 мг
```
Скрипт даёт «токсичным» доп-зазор 0.8 (`UL_SAFE`: a, d, iron, zinc, selenium), а b3, b9,
calcium, phosphorus идут без зазора — потому они и упираются ровно в UL (см. ниже).

## 2. Пресетные дни (реальные связки) — приоритет

### 2а. Свой вес группы каждого якоря — как выдаётся клиенту
**0 нарушений IOM UL** на всех 7140 днях. Максимальные суточные суммы (доля UL):

| Нутриент | max доля UL | где |
|---|---|---|
| vitamin_b9 (фолат) | **x1.000** (1000 мкг) | anchor 155 (f80p) день 6 |
| vitamin_b3 (ниацин) | **x1.000** (35 мг) | anchor 53 (m90p) день 15 |
| calcium | x0.996 (2491 мг) | anchor 189 (m90p) день 2 |
| phosphorus | x0.943 (3772 мг) | anchor 29 (m90p) день 0 |
| iron | x0.800 (36 мг) | anchor 8 (m90p) день 21 |
| selenium | x0.800 (320 мкг) | anchor 207 (f80p) день 18 |
| vitamin_a | x0.795 (2384 мкг) | anchor 94 (f80p) день 11 |
| zinc | x0.701 · vit_d x0.45 · iodine x0.21 · vit_c x0.20 · b6 x0.05 · vit_e x0.02 | — |

Значения b3/b9/calcium/phosphorus вплотную к UL — это **не баг, а точка отсечки билдера**
(у них нет 0.8-буфера). Важно: UL для **пищевых** ниацина и фолата фактически не лимитируют —
IOM-овские 35 мг/1000 мкг относятся к синтетической/обогащённой форме (флашинг ниацина,
маскировка B12-дефицита фолиевой кислотой), а не к ниацину/фолату из еды. То есть даже x1.0
здесь токсикологически безопасно. Держать в уме, но чинить нечего.

### 2б. Для целевого персонажа (мужчина, набор массы → группы m90/m90p)
Только якоря групп m90/m90p, свой вес — **макс x1.000 (B3, B9), всё остальное ниже UL.**
Персонаж на наборе массы получает безопасное меню.

### 2в. Псевдо-нарушения при насильном m90p на «женских» якорях (артефакт)
Если ПРИНУДИТЕЛЬНО применить вес m90p к пресетам, собранным под лёгкие группы (f60/f80/f80p),
всплывает: calcium 47 дней (макс x1.22), vitamin_b3 1693 дня, vitamin_b9 1321 день, selenium 9,
iron 4, phosphorus 3. **НО** все виновники — якоря нативных групп f60/f80/f80p/m70/m90
(разбивка по группам в анализе). В приложении такого не бывает: тяжёлый мужчина получает
m90p-якоря (собранные под m90p UL), а не женские. **Это не реальный риск, а следствие моего
worst-case форсажа веса.**

### Из ПОЛНОЙ базы (3736 блюд), для справки (ещё выше):
vitamin_b9 x6.40, vitamin_a x4.91 (стек куриной печени 2400–3200 мкг/порция), vitamin_b3 x4.77,
calcium x3.16, iron x2.75, selenium x2.58, phosphorus x1.97, zinc x1.56, vitamin_d x1.54.

**Самые опасные при стакинге (токсикологически значимые, не «пищевой B3/B9»):**
1. **selenium x2.57** — морепродукты (кальмары/креветки/тунец). Селен реально токсичен при хронике.
2. **vitamin_a x2.25** — блюда из печени (fr_227369/fr_209472 и печёночные паштеты 2400+ мкг ретинола/порция). Ретинол — тератоген/гепатотоксичен.
3. **calcium x2.40**, **iron x2.08**, **zinc x1.47**, **phosphorus x1.74** — реальны, но требуют
   намеренного подбора моно-тематического дня (весь день сыр/тофу, или весь день бобовые).

## 4. ЕДИНСТВЕННАЯ находка, требующая внимания (major)

**Рантайм НЕ проверяет суточный UL при ручных заменах блюд.**
`app-v2/cabinet.html` содержит `portionCorridor`/`maxWeightWithCaps`/`scaleRecipe`/
`rebalanceDayMacros`, но **ни одной проверки суммарных микро за день** (grep по
`UL/selenium/vitamin_b9/micronutrient` в cabinet.html — совпадений по логике нет).
`rebalanceDayMacros` балансирует только 4 макроса (ккал/Б/Ж/У).

- **Severity: major** (не critical: пресеты безопасны, нужен намеренный ручной стакинг).
- **Вектор:** пользователь через карусель/«замени завтрак» вручную набирает день из
  однотипных высоко-X блюд (напр. кальмары в 3 слота → селен x2.5; или печёночные →
  ретинол x2+). Билдер такой день бы отбраковал, а рантайм-своп — пропустит.
- **Предложение (НЕ реализовано):** добавить в рантайм лёгкий сторож суточного UL по
  «токсичной» короткой пятёрке — **selenium, vitamin_a(ретинол), iron, zinc, calcium**
  (именно они дают реальную токсичность; B3/B9 из еды не считать). При замене/добавлении
  блюда суммировать `micronutrients_per_portion` дня по текущей группе; если >UL·0.9 —
  мягкая плашка «в этот день много X, лучше разнести». Не блокировать жёстко, т.к. данные
  медианные по категориям (не абсолют).
- **Смежные функции (impact-трейс):** логика замен (verbs `замени/поменяй`, ~стр. 2853/3261/3654),
  `_swapHist`/`_swapPos` (3482), сортировка карусели (`carousel[mealType]`). Сторож ставить
  в точке применения свопа + при первичной сборке дня (после `rebalanceDayMacros`, ~5107).

## 5. Итоговый вердикт

| Вопрос | Ответ |
|---|---|
| Есть ли UL-нарушения в ПРЕСЕТАХ (нужно чинить данные)? | **Нет.** Билдер отсекает по суточному UL. |
| Безопасен ли целевой персонаж (муж, набор массы, m90p)? | **Да.** Макс x1.000 по пищевым B3/B9, остальное ниже. |
| Реален ли стакинг выше UL? | Только **теоретический worst-case** при ручном подборе моно-тематического дня. |
| Что чинить? | **1 пункт (major):** нет рантайм-сторожа суточного UL при ручных заменах — предложить мягкую плашку по 5 токсичным нутриентам. |
| Ложные тревоги | Форсаж m90p на женских якорях (артефакт теста); высокие ×UL по B3/B9 — пищевые формы, не токсичны. |

Метод воспроизводим: `micronutrients_per_portion.json` (веса групп) × `anchors_seeds.json`
(связки id по слотам), UL из IOM/NIH = зашитым в `build_super_presets.py:46`.
