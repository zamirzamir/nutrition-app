# Параллелизация офлайн-сборки пресетов (16.07)

`build_super_presets.py` и `fix_poor_anchors.py` переведены с одного ядра на пул процессов
(`multiprocessing`, start-метод **spawn** — родной для macOS). Алгоритм поиска, скоринг,
пороги (±3%, UL, дека, RDA/UL-таблицы) и формат выходных файлов **не менялись** — изменено
только распределение якорей по процессам и порядок записи результатов.

Бэкапы до правок: `_АРХИВ/build_super_presets_20260716.py`, `_АРХИВ/fix_poor_anchors_20260716.py`.

## Как запускать (MacBook M2 Pro, 16 ГБ)

```bash
cd ~/Claude/Projects/nutrition-app   # или где лежит проект — из папки со скриптами и recipes.json

# Ночная пересборка супер-пресетов: 150 сек/якорь, 8 воркеров
python3 build_super_presets.py 150 --workers 8

# Починка бедных якорей: 120 сек/якорь, 8 воркеров
python3 fix_poor_anchors.py 120 --workers 8
```

- `--workers` необязателен: по умолчанию берётся `все ядра − 2` (на 10-ядерном M2 Pro = 8;
  два ядра остаются системе). **8 — рекомендованное значение**, вручную менять не нужно.
- Первый позиционный аргумент — сек/якорь, как раньше (`python3 build_super_presets.py 150`
  по-прежнему работает).
- Ускорение ≈ ×8: то, что занимало ~6 ч (238 якорей × 90 с), займёт ~45–50 мин;
  238 × 150 с ≈ 1 ч 15 мин вместо ~10 ч.
- Память: каждый воркер грузит свою копию данных (recipes + микронутриенты, ~130–150 МБ).
  8 воркеров ≈ 1.2–1.3 ГБ — для 16 ГБ безопасно. Больше 8–10 воркеров ставить не стоит.

## Что изменено (диф по сути)

### build_super_presets.py
1. Разбор аргументов: было `sys.argv[1]` (время), стало `argparse` — то же позиционное время
   + необязательный `--workers N` (default `max(1, cpu_count()-2)`).
2. Тело цикла «один якорь» вынесено в `_process_anchor(task)` — внутри тот же код:
   `build_super_seed(T)` + запись чекпоинта `seeds_super/anchor_NNN_группа.json`.
   Имя чекпоинта уникально по индексу якоря → каждый файл пишет ровно один процесс, гонок нет.
3. Родитель заранее сканирует чекпоинты (пропуск полных 30-дневных — логика та же) и раздаёт
   **только недостающие** якоря пулу через `imap_unordered`; один якорь достаётся ровно одному
   воркеру. `SUPER_LIMIT` (env для смоука) работает как раньше.
4. Финальная сборка `anchors_seeds_SUPER.json` и отчёт `super_presets_report.md` — без изменений,
   выполняются одним (родительским) процессом в конце.
5. Прогресс: воркеры печатают `[pid N] старт якоря i/238 …`, родитель — итог по каждому
   готовому якорю с ETA. Строки могут идти вперемешку — это нормально.
6. Весь драйвер обёрнут в `main()` + `if __name__ == '__main__'` (обязательно для spawn на macOS).

### fix_poor_anchors.py
1. Те же аргументы: позиционное время + `--workers N` (default `ядра − 2`).
2. Воркер `_fix_one` только считает `rebuild(an)` (логика не тронута) и **возвращает** результат.
   **Воркеры на диск не пишут вообще.**
3. Родитель принимает результаты, применяет защиту «не ухудшать» (строго больше уникальных — иначе
   оставляем старое) и пишет `anchors_seeds.json` **один раз в конце**. `.poor_attempted.json` —
   тоже один раз в конце. Гонок записи нет по построению.
4. ⚠️ Изменение поведения при прерывании (единственное): раньше файл сохранялся после каждого
   удачного якоря, теперь — только в конце. Прервал Ctrl-C до конца → на диске ничего не поменялось
   (ни пресеты, ни отметки «пробовано») — просто запусти заново, бедных якорей единицы, потеря
   минут, зато файл никогда не остаётся полузаписанным.
5. Бэкап `anchors_seeds.json` перед запуском — по-прежнему делается вручную до старта (как в докстринге).

## На что обратить внимание
- **Старт не мгновенный**: каждый воркер при запуске сам грузит ~25 МБ JSON (5–10 с) — первые
  строки прогресса появятся с задержкой, это норма.
- Вердикт «⚠️ регресс» в отчёте смоука — следствие 5 с/якорь; на боевых 90–150 с не показатель.
- ETA считается по завершённым якорям — в начале прогона скачет, дальше выравнивается.
- Если якорей к расчёту меньше, чем воркеров, пул автоматически сожмётся до их числа.
- `fix_poor_anchors.py`: если понадобится перечинить уже «пробованные» якоря — удалить
  `.poor_attempted.json` (как и раньше).
