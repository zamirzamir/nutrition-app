## 4. Перегенерация micronutrients_per_portion.json — СДЕЛАНО

- Отдельного скрипта-генератора в репо нет (grep: файл только читается/точечно патчится; создатель — исторический). Алгоритм восстановлен из `add_recipe.py::per100` (единственное место, где записи создаются): per100g = Σ(micro_i × amount_g_i)/Σ(amount_g), затем на группы `recipes.portions[g].g`, округление до 3 знаков. Флаг `fry` на микро не влияет (в cabinet.html absorb_ratio применяется только при его наличии в рецепте; в recipes.json его нет ни у одного ингредиента).
- **Проверка алгоритма до записи:** на актуальной базе 2408 из 3736 блюд воспроизводятся побайтно; расхождения остальных — дрейф старого MP (он от 09.07 02:14, а микро-таблица правилась 11–15.07 + вылеченные дыры) и шум округления малых значений. Полевая структура расхождений (vitamin_k/fiber/calcium/C у сотен блюд) подтверждает: это правки таблицы, а не ошибка алгоритма.
- Результат: **3736 блюд (все), обновлено 3015**, новых/потерянных id нет, шапка (`unit`, `fields`) сохранена, старый файл в `_АРХИВ/`.
- `validate_presets.py` на новом MP: **макро ±3% — 0 нарушений из 7140 дней**; все id пресетов находят порции.
