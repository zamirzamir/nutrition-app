## 8. Осталось незакрытым из M7 — подтверждаю, ОБЕ подчасти актуальны

**8а. «Съел» слетает после F5.** Механизм: `toggleMealEaten` хранит метку в `_eatenCards`/`_eatenRecipes`
(cardId + id рецепта) и ставит `slot.frozen = true` только на ЖИВОМ объекте слота (6630).
После F5 день строится заново; frozen не восстановлен (см. 8б) → первый же `rebalanceDayMacros`
внутри сборки может ЗАМЕНИТЬ блюдо незамороженного слота (5194/5316 пропускают только m.locked/m.frozen).
Если рецепт слота стал другим — `buildMealNav` (6589–6592) ТИХО УДАЛЯЕТ метку («метка не переносится
на чужое»). Т.е. слетание — прямое следствие невосстановленного frozen + недетерминированности ребаланса.

**8б. frozen не восстанавливается после пересборки.** `slot.frozen` ставится ТОЛЬКО в toggleMealEaten;
ни restoreProgress, ни applyLockedDishes, ни сборщики дня его не восстанавливают из `_eatenCards`.

**Где чинить (одно место закрывает обе):** в `applyLockedDishes` (6541) — он уже зовётся во всех трёх
сборщиках — дополнительно пройти слоты: `cardId = (dayIndex===1 ? 'recipe-'+idx : 'dr-'+dayIndex+'-'+idx)`;
если `_eatenCards.has(cardId)` и `_eatenRecipes[cardId] === slot.recipe.id` → `slot.frozen = true`.
Нюанс: applyLockedDishes выполняется ПОСЛЕ первого rebalanceDayMacros (4088→4089, 4933→4941, 5084→5085),
который уже мог увести съеденное блюдо — поэтому либо восстанавливать eaten-frozen ДО первого ребаланса
(в начале сборки), либо после восстановления в applyLockedDishes гнать его встроенный до-ребаланс
(6566–6578 уже умеет). Плюс тот же нюанс кэша из п.5 (дни 2+, построенные списком покупок до restore).
